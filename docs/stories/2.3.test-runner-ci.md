# Story 2.3: Modernizar o Runner de Testes e Observabilidade de CI

## Status

Done

## Story

**As a** desenvolvedor e equipe de QA/DevOps do PainelAtende,
**I want** um runner de testes com auto-descoberta dinâmica, timeout por teste, geração de JUnit XML, relatórios de cobertura e artefatos de falha,
**so that** a suíte de testes seja resiliente, expansível sem manutenção manual de listas e forneça observabilidade detalhada na execução local e no CI.

## Acceptance Criteria

1. **Auto-descoberta Dinâmica de Testes**:
   - `tests/run-all.js` descobre dinamicamente todos os arquivos `*.test.js` na pasta `tests/` via leitura de diretório (`fs.readdirSync`), eliminando a lista manual estática.
   - Novos testes criados na pasta `tests/` são automaticamente executados sem necessidade de alteração no runner.

2. **Timeout Configurável por Teste**:
   - Cada teste individual possui um timeout limite (padrão: 30.000 ms).
   - Testes que excederem o timeout são encerrados com falha explícita, registrando o evento no relatório e no console.

3. **Geração de Relatório JUnit XML**:
   - O runner gera automaticamente um arquivo JUnit XML em `reports/junit.xml` contendo contagem de testes, suítes, tempos de execução e detalhes de falhas/erros.

4. **Geração de Artefatos de Falha**:
   - Quando um ou mais testes falham (ou estouram o timeout), o runner salva um artefato de logs de falha em `reports/failures/<nome-do-teste>-<timestamp>.log` com stdout, stderr, código de saída e tempo decorrido.

5. **Suporte a Cobertura de Código e Script dedicado**:
   - Adicionado script `"test:coverage"` em `package.json` para rodar a suíte registrando métricas de cobertura com Node (`node --experimental-test-coverage` ou V8 coverage).
   - `tests/run-all.js` aceita a flag `--coverage` para habilitar/relatar cobertura de código dos módulos em `js/`.

6. **Observabilidade e Artefatos no GitHub Actions**:
   - Atualizado `.github/workflows/ci.yml` armazenando o relatório JUnit `reports/junit.xml` e artefatos de falhas como artefatos do workflow (`actions/upload-artifact@v4`).

7. **Gates de Qualidade**:
   - Todos os quality gates (`npm run lint`, `npm run typecheck`, `npm run build`, `npm test`, `npm run test:coverage`) passam sem erros.
