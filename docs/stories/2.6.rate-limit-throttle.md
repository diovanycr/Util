# Story 2.6: Proteção contra Rate Limiting no Firestore

## Status

Done

## Story

**As a** desenvolvedor e usuário do PainelAtende,
**I want** proteção contra throttling/rate limiting no carregamento de mensagens e problemas no Firestore,
**so that** trocas frequentes de abas ou ações repetidas na interface não causem consumo excessivo de leituras do banco ou travamentos por requisições concorrentes.

## Acceptance Criteria

1. **Utilitário Reutilizável de Throttle (`js/core/throttle.js`)**:
   - Criar `createLoadThrottle({ minIntervalMs, now })` com clock injetável para testes unitários sem dependência de timers de sistema.
   - Criar `createConcurrencyGuard()` para evitar requisições sobrepostas.
   - Suporte a flag `{ force: true }` para operações explícitas que exigem recarregamento (ex: criação/edição/remoção).
   - Suporte a reset e recuperação imediata após falhas/exceções.

2. **Integração nas Mensagens (`js/modules/messages/loader.js`, `js/modules/messages.js`)**:
   - Aplicar `createLoadThrottle` com `minIntervalMs: 2000` em `loadMessages`.
   - Garantir que mutações (adicionar, editar, remover, duplicar) usem `{ force: true }`.
   - Integrar `reset()` no `resetMessages()`.

3. **Integração nos Problemas (`js/modules/problems.js`)**:
   - Aplicar `createLoadThrottle` com `minIntervalMs: 2000` em `loadProblems`.
   - Permitir `append: true` (paginação) sem ser bloqueado pelo throttle de full reload.
   - Fornecer wrapper `_forceLoadProblems` para mutações e trocas forçadas.
   - Integrar `reset()` no `resetProblems()`.

4. **Suíte de Testes Unitários (`tests/throttle.test.js`)**:
   - Testar primeira chamada imediata, bloqueio dentro do intervalo, liberação após intervalo expirar.
   - Testar bloqueio de chamadas concorrentes.
   - Testar método `isThrottled()`, `reset()`, e comportamento diante de exceções.

5. **Quality Gates**:
   - Todos os quality gates (`npm run lint`, `npm run typecheck`, `npm run build`, `npm test`) passando com 100% de sucesso.
