# Story 2.7: Paginar e Agregar Leituras do Firestore

## Status

Done

## Story

**As a** desenvolvedor e usuário do PainelAtende,
**I want** paginação baseada em cursor no carregamento de mensagens e agregação inteligente em memória no módulo de Analytics,
**so that** o consumo de leituras do Firestore seja drasticamente reduzido, prevenindo latência e custos excessivos à medida que a base de dados cresce.

## Acceptance Criteria

1. **Paginação por Cursor em Mensagens (`js/modules/messages/loader.js`)**:
   - Substituída a busca fixa de 500 itens por paginação baseada em cursor `startAfter` com `MSG_PAGE_SIZE = 50`.
   - Adicionada flag `append: true` em `loadMessages` para suporte ao carregamento incremental.
   - Renderizado botão "Carregar mais mensagens" (`#btnLoadMoreMsgs`) no final da lista quando houver mais itens.
   - Exposta função `resetMsgPagination()` para limpar o cursor `_lastMsgDoc` ao deslogar ou redefinir mensagens.

2. **Gerenciamento do Cursor no Módulo Principal (`js/modules/messages.js`)**:
   - Integrado `resetMsgPagination()` ao procedimento de `resetMessages()`.

3. **Otimização e Agregação do Analytics (`js/modules/analytics.js`)**:
   - Refatorado `loadAnalyticsData()` para reaproveitar os arranjos locais em memória `allMessages` e `allProblems` quando disponíveis.
   - Eliminadas requisições `getDocs` redundantes em toda a coleção a cada evento de cópia (`copy-count-updated`).

4. **Suíte de Testes Unitários (`tests/pagination-analytics.test.js`)**:
   - Criados testes de verificação da paginação em `loader.js`, gerenciamento do cursor em `messages.js` e reutilização de dados locais em `analytics.js`.

5. **Quality Gates**:
   - Todos os quality gates (`npm run lint`, `npm run typecheck`, `npm run build`, `npm test`) passando com 100% de sucesso.
