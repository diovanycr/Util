# Story 2.1: Evoluir o Typecheck de Sintaxe para Contratos JavaScript (JSDoc + `checkJs`)

## Status

Done

## Story

**As a** desenvolvedor e maintainer do PainelAtende,
**I want** que o `npm run typecheck` valide não apenas sintaxe básica, mas contratos de tipos, imports e assinaturas via JSDoc e TypeScript com `allowJs` e `checkJs`,
**so that** possamos capturar erros de runtime, propriedades inexistentes e imports incorretos durante a integração contínua e desenvolvimento local.

## Acceptance Criteria

1. `typescript` é instalado como `devDependency` no `package.json`.
2. O arquivo `tsconfig.json` é criado configurando `allowJs: true`, `checkJs: true`, `noEmit: true` e resolução ESM.
3. `scripts/typecheck.js` executa a validação de contratos de tipos via TypeScript (`tsc --noEmit`) além de/em conjunto com o check de sintaxe Node.js.
4. JSDoc annotations são adicionadas aos módulos principais (`js/core/utils.js`, `js/core/modal.js`, `js/core/toast.js`, `js/modules/*`, `scripts/*`) para garantir tipagem clara de parâmetros e retornos.
5. `npm run typecheck` passa sem nenhum erro de tipo ou compilação em 100% dos arquivos JavaScript do repositório.
6. Teste automatizado `tests/typecheck-contract.test.js` valida que `tsconfig.json` possui `checkJs: true` e que `npm run typecheck` roda `tsc --noEmit` com sucesso.
7. Todos os quality gates (`npm run lint`, `npm run typecheck`, `npm run build`, `npm run validate:port-denylist`, `npm test`) passam sem erros.

## Dev Notes

- O projeto é JavaScript Vanilla sem bundler/transpilação.
- O uso de `checkJs: true` permite checar arquivos `.js` via JSDoc sem requerer conversão para `.ts`.
- `tsc --noEmit` lê as configurações de `tsconfig.json`.
