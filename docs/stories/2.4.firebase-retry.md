# Story 2.4: Testar e Aprimorar Política de Retry do Firebase

## Status

Done

## Story

**As a** desenvolvedor e usuário do PainelAtende,
**I want** uma política de retry robusta com backoff exponencial, jitter, limite de tentativas, cancelamento e clock/sleeper injetável nas operações do Firebase,
**so that** falhas temporárias de rede sejam recuperadas automaticamente sem travar a interface nem gerar loops de chamadas.

## Acceptance Criteria

1. **Abstração Reutilizável de Retry (`js/core/retry.js`)**:
   - Criado módulo utilitário de retry parametrizável aceitando `maxRetries`, `initialDelayMs`, `maxDelayMs`, `backoffFactor`, `jitter` e injeção de `sleeper`/`clock` para testes unitários sem esperas reais de tempo.
   - Suporte a cancelamento via `AbortSignal`.

2. **Integração nas Operações Críticas do Firebase/Firestore**:
   - Aplicada a política de retry em `js/core/firebase-retry.js` envolvendo operações de mensagens, links e problemas (`getDocs`, `getDoc`, `addDoc`, `updateDoc`, `setDoc`, `deleteDoc`, `writeBatch`).
   - Feedback visual ao usuário durante a tentativa de reconexão.

3. **Suíte de Testes Unitários de Retry (`tests/firebase-retry.test.js`)**:
   - Criado `tests/firebase-retry.test.js` com injeção de sleeper simulado validando:
     - Erros recuperáveis (`unavailable`, `resource-exhausted`, `network-request-failed`) com sucesso na 2ª ou 3ª tentativa.
     - Limite de tentativas estourado lançando o erro original após o número máximo de retries.
     - Erros não recuperáveis (`permission-denied`, `unauthenticated`, `invalid-argument`) falhando imediatamente sem retry.
     - Interrupção por cancelamento/abort.

4. **Gates de Qualidade**:
   - Todos os quality gates (`npm run lint`, `npm run typecheck`, `npm run build`, `npm test`) passam sem erros.
